# DigitLab 原理与实现说明

这份文档面向想读懂代码、或在课堂上讲解神经网络的读者。它解释 DigitLab 的每个关键决策：
数据如何进入网络、前向/反向传播怎么算、界面上的可视化和数字之间是什么关系。

## 1. 整体数据流

```
鼠标 / MNIST 图片
      │
      ▼
BufferedImage 320×320（白底黑字）
      │  Preprocessor
      ▼
28×28 灰度向量（784 个 0..1 的 double）
      │  Network.forward / trace
      ▼
隐藏层 64 (ReLU) → 隐藏层 32 (ReLU) → 输出 10 (Softmax)
      │
      ├── 概率条 / 最大概率数字
      └── ForwardTrace → 神经网络可视化（激活、权重、脉冲动画）
```

训练时方向相反：输出概率与真实标签比较得到误差，再逐层把误差传回去，更新每个权重。

## 2. 为什么是 784 → 64 → 32 → 10

- **784 = 28×28**：MNIST 的标准输入尺寸，每个像素是一个特征。
- **64 + 32 两个隐藏层**：足够拟合手写数字这种中等复杂度的分类问题，同时参数只有 52,650 个，
  一个 epoch 在普通 CPU 上约 3 秒，适合课堂现场演示。
- **10 个输出**：数字 0–9。Softmax 保证输出是非负且和为 1，可以解释为“模型认为的概率”。

更宽的网络（如 128-64）通常能再高零点几个百分点，但训练更慢，可视化也更拥挤。
教学项目的重点不是刷榜，而是让每一层、每一个连接都能被看见。

## 3. 前向传播

对第 `l` 层：

```
z[l] = W[l] · a[l-1] + b[l]
a[l] = ReLU(z[l])        （隐藏层）
a[L] = Softmax(z[L])     （输出层）
```

ReLU：`max(0, z)`，计算简单、缓解梯度消失，并让隐藏层的激活具有稀疏性——
可视化里很多节点是暗的，这正是 ReLU 的效果。

Softmax：

```
p_i = exp(z_i - max(z)) / Σ_j exp(z_j - max(z))
```

减去最大值是为了数值稳定，结果不变。界面上的 10 条概率条就是这里的 `p_i`。

## 4. 损失函数

训练使用交叉熵：

```
L = -log(p[真实标签])
```

如果模型给正确答案的概率是 0.99，损失约 0.01；如果只给 0.01，损失约 4.6。
一个 batch 的损失取平均。

## 5. 反向传播

记输出层误差 `δ[L] = p - onehot(label)`——这是 Softmax + 交叉熵组合的一个漂亮结论，
不需要再乘 Softmax 的导数。然后从后往前：

```
dW[l] = δ[l] · (a[l-1])ᵀ
db[l] = δ[l]
δ[l-1] = (W[l]ᵀ · δ[l]) ⊙ ReLU'(z[l-1])
```

最后对 batch 求平均，加上 L2 正则项，交给优化器更新。

实现位置：`src/main/java/digitai/nn/Network.java` 的 `trainBatch` 方法。
代码里没有自动微分框架，所有循环都是显式写出来的，适合逐行阅读。

## 6. 优化器

默认使用 **Adam**：

```
m = β1·m + (1-β1)·g
v = β2·v + (1-β2)·g²
θ = θ - lr · (m/(1-β1ᵗ)) / (sqrt(v/(1-β2ᵗ)) + ε)
```

Adam 为每个参数维护一阶、二阶动量，相比朴素 SGD 对学习率更不敏感，适合交互式训练。
界面里也可以切换到 SGD，观察两者收敛曲线的差异。

参数初始化使用 **He 初始化**：`W ~ N(0, 2/fanIn)`，配合 ReLU 能让信号在前向/反向时保持合理方差。

## 7. 预处理为什么重要

网络只认识 MNIST 风格的图片：数字大约 20×20、居中、黑字白底、笔画浓度接近。
鼠标画出来的数字可能偏小、偏左、很细或很粗。`Preprocessor` 做了这些事：

1. **取墨水浓度**：白底黑字时 `ink = 1 - luminance`；透明画布时用 alpha 作为笔画强度。
2. **去噪**：低于 0.02 的像素视为背景，避免抗锯齿噪点干扰包围盒。
3. **裁包围盒**：只保留有笔画的区域。
4. **等比缩放**：最长边缩放到 20 像素，保持数字比例，不把它拉扁。
5. **重心居中**：把墨水重心移到 28×28 的中心 `(14, 14)`，而不是简单按包围盒居中。
6. **亮度归一化**：让最浓的像素为 1，减少不同笔刷粗细/颜色带来的影响。

任何一步做错，都会让“画得很像”的数字识别失败。这也是界面里同时显示 28×28 预览的原因：
你可以看到网络真正“看到”的输入，而不只是漂亮的画板。

## 8. 神经网络可视化

### 8.1 布局

- **输入层**：不画 784 个点（会糊成一片），而是直接显示 28×28 灰度缩略图。
- **隐藏层 64**：8×8 点阵；**隐藏层 32**：8×4 点阵。节点颜色亮度 = 激活值。
- **输出层 10**：竖排 10 个节点，标注 0–9 和概率。
- **连接线**：全连接层有 784×64 ≈ 5 万条边，不可能全画。`NetworkView` 按 |权重| 排序取样，
  最多画约 500 条，透明度/粗细映射强度，既保留结构感又不糊屏。

### 8.2 激活动画

识别时调用 `Network.trace(input)` 拿到 `ForwardTrace`：每层的激活值、ReLU 之前的 z 值。
界面用 Swing Timer 按层点亮节点，并让光点沿“贡献最大的连接”从输入流向输出，
让“前向传播”这个抽象概念变成一个可以看见的过程。

### 8.3 点击神经元

点击一个隐藏层节点时，界面显示：

- 该节点与上一层所有神经元连接的权重；
- 对于第一隐藏层，这就是一个 28×28 的**权重热图**，可以直观看到它偏爱哪种笔画（竖线、圆弧、交叉……）；
- 点击输出节点则显示它从第二隐藏层接收的权重，以及它对 10 个类别的输出概率贡献。

这些权重是训练的直接产物，不是预先设计的特征。教学时可以问：
“为什么 64 个神经元里，有的对横线敏感、有的对圆圈敏感？”——这正是表示学习的直观入口。

## 9. 训练流程与线程模型

- `Trainer.trainEpoch` 负责打乱数据、切 batch、调用 `Network.trainBatch`，并在每个 batch 后回调。
- GUI 把训练放在 `SwingWorker` 的后台线程，`BatchListener` 通过 `publish/process` 回到 EDT 更新曲线和进度。
- 暂停在 batch 边界检查；停止会让 listener 返回 false，当前 epoch 提前结束。
- 单次推理（含 trace）在毫秒级，可以直接在 EDT 做；画板输入用 150ms 防抖，避免每个鼠标点都推理。

## 10. 模型文件格式

`Network.save` 写一个大端二进制文件：

```
int magic = 0x44474C42 ("DGLB")
int version = 1
int layerCount (含输入层)
int[layerCount] sizes
long seed
每一层：double[out] biases
         double[out][in] weights（行优先）
```

文件约 412 KB，加载时校验 magic、版本、层数、尺寸，损坏时抛出可读的 IOException，
GUI 会降级到“未加载模型”状态而不是崩溃。

## 11. 项目结构与阅读顺序

建议按以下顺序阅读：

1. `data/MnistLoader.java` — 数据从哪里来；
2. `data/Preprocessor.java` — 画板如何变成网络输入；
3. `nn/Network.java` — 前向传播、反向传播、Adam；
4. `nn/Trainer.java` — 训练循环；
5. `nn/ForwardTrace.java` — 可视化所需的中间结果；
6. `ui/NetworkView.java` — 如何把数学画出来；
7. `ui/RecognitionPanel.java` / `ui/TrainingPanel.java` — 交互与线程；
8. `tools/TrainCli.java` — 不经过界面也能训练。

## 12. 可以继续做的实验

- 把隐藏层改成 `128,64`，比较测试准确率和训练时间。
- 把优化器换成 SGD，观察 loss 曲线的抖动。
- 只用 1,000 张训练样本，观察过拟合/欠拟合。
- 改变预处理（不居中去、不缩放），量化准确率下降。
- 在 `NetworkView` 里点击不同隐藏神经元，比较权重热图。
- 给训练增加数据增强（随机平移/旋转/加粗），观察手写风格鲁棒性变化。
- 把 MLP 换成小型 CNN，作为进阶任务（需要自己补卷积/池化层）。
